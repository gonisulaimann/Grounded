Reference integrity firewall

Find what your code contradicts.

Grounded reads the comments, doc examples, imports and config strings in a repository and reports the ones that contradict the code they live in — a call that resolves nowhere, a path that does not exist, a default the code disagrees with. It fires only on mechanical contradiction.

Why a rule can be trusted

A clean scan means something. A finding means something.

Linters that guess produce noise, and noise gets muted. Grounded only reports what the repository itself can prove, and stays silent when it cannot see enough to be sure. Every finding carries the claim, the evidence, and a fix.

LIE · error

A name that resolves nowhere

A comment calls get_user() and no such function exists in the repo, is imported in the file, or is used anywhere. These are renames that left the comment behind. Exit code 1 by default.

DRIFT · warning

A number the code disagrees with

A comment states a timeout, port, limit or threshold that no longer matches the code beside it. Warning severity: real rot, but not a broken build.

SMELL · note

An anchor with nothing to hold

Bare see above, line 42 anchors, and HACK/XXX/kludge markers with no ticket, no expiry condition, and no way to verify them later.

What stays silent by design: imported names, standard-library and platform calls, parameters and locals, docstring field lists (:param:, @param), illustrative examples (“for example …”), commented-out code, guarded imports, parse-failed files, and any path the scan never indexed. The trade is deliberate: recall for precision.

The rule set

Eleven contradictions, each with a name

Seven run by default and gate on lie. Four ship opt-in and graduate to default-on only by measured precision on real repositories — never by volume.

Default severity is shown per rule. --enable / --disable switch any of them.
RuleSeverityWhat it reports
stale-symbol-ref LIE A comment names a call that resolves nowhere — not defined in the repo, not imported here, not used here. Prints rename suggestions when a close match exists.
stale-import LIE A resolvable import whose module is missing, or whose name is not defined, re-exported, or a submodule there. Python, JS/TS relative imports, tsconfig aliases resolved.
stale-file-ref LIE A comment claims a path inside the repo tree that does not exist. Other projects, framework namespaces and placeholders are ignored.
stale-entrypoint LIE A [project.scripts] target or a package.json bin/main path pointing at nothing in the repo.
stale-mock-ref LIE A @patch string naming a symbol absent from the in-repo module — the test that errors at runtime.
number-drift DRIFT A comment states a magic number that disagrees with adjacent code.
fragile-anchor SMELL Line anchors and see above without a symbol; workaround markers with no ticket or expiry.
stale-doc-ref opt-in LIE A fenced doc example calling a symbol defined nowhere in the repo.
stale-contract-ref opt-in LIE DRIFT A deprecation target, lock claim, or env default that contradicts the repo.
phantom-package opt-in DRIFT An import declared in no manifest — a dependency that happens to work locally.
ghost-export opt-in SMELL A public symbol with no importers, no use, and no deliberate API marking.

Built for the loop

Made for agents that edit faster than they read

An assistant renames a function and leaves the comment behind. An hour later another assistant trusts the comment and builds against a call that does not exist. Grounded is the check that runs between those two moments.

MCP server stdio

Three tools for agents that speak Model Context Protocol: check_path, explain_checker, and blast_radius — everything touching a symbol before you rename it. Filesystem access is confined to the server root.

LSP 3.17 editors

grounded lsp speaks Language Server Protocol over stdio: instant diagnostics (lie as error, drift as warning, smell as information) plus quick-fix actions for unambiguous renames and moved paths. Neovim, VS Code, Cursor, Zed, Emacs.

Hooks and CI gate

grounded scan <file> checks one file and exits non-zero on findings — the contract Aider’s --lint-cmd and an editor PostToolUse hook expect. Plus a first-party GitHub Action and a pre-commit hook. 

# MCP, for agents that can use tools directly
{
  "mcpServers": {
    "grounded": { "command": "grounded", "args": ["mcp", "--root", "."] }
  }
}
# Claude Code: after every edit, check the diff
{
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [{ "type": "command",
                    "command": "grounded scan . --changed --quiet" }] }
    ]
  }
}

Adopting on an existing codebase

Start from today, not from zero

Two mechanisms, composable. Both keep the full-tree scan and filter reporting only — the index is still built from the whole tree, because cross-file resolution needs it. 

# record today's findings once, commit the baseline, gate on the delta
$ grounded baseline . --output .grounded-baseline.json
$ git add .grounded-baseline.json
$ grounded scan . --baseline .grounded-baseline.json

# fingerprints cover rule, path and claim text — never line numbers
# gate pull requests on changed lines only
$ grounded scan . --changed              # working tree vs HEAD
$ grounded scan . --changed origin/main  # branch vs base (CI)

# rename fallout on untouched lines still reports: a finding whose
# claim names a symbol the diff touched is never filtered away.

What it deliberately does not do

Scope is a feature

  • Docstring contracts (parameter lists, return sections, raised exceptions) are covered precisely by darglint and pydoclint for Python and eslint-plugin-jsdoc for JS/TS. Grounded names the incumbent instead of duplicating it.
  • Commented-out code is Ruff ERA001’s job. Grounded uses those blocks only as suppression evidence.
  • Unverbed name mentions are skipped. A rename noted without backticks or a reference verb is missed — recall traded for precision.
  • Syntactic, not semantic. JavaScript/TypeScript, Go and C analysis reads imports and identifiers, not a full type graph.
  • Framework namespaces stay silent (template paths, URL names). Platform APIs named in prose can still report — judged on sight.
  • Partial scans never claim absence for what they did not index: a sub-tree scan can only ever report fewer findings than its enclosing root, never more.

Install

No Python management required

A standalone binary, a Homebrew tap, or the Python package. It exits 1 when any finding meets --fail-on (default: lie), so the default is already a usable CI gate.

macOS · Linux

One line, standalone binary

curl -fsSL https://raw.githubusercontent.com/gonisulaimann/Grounded/main/install.sh | sh

Installs the standalone binary, or defers to an existing uv/pip/brew.

Windows

PowerShell

irm https://raw.githubusercontent.com/gonisulaimann/Grounded/main/install.ps1 | iex

Same standalone binary path on Windows.

Python 3.10+

pip · uv

pip install grounded-lint

uvx --from grounded-lint grounded scan .

uvx runs it with no install step at all — measured 0.05 s cached startup.

Homebrew

Tap

brew install gonisulaimann/tap/grounded

And from source: git clone, then pip install -e ..
